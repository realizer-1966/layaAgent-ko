# 브라우저 탭 안의 에이전트: 322M 인코더가 결정하고, 작은 LLM은 물었을 때만 나선다

> 이 글은 원본 [layaAgent 아티클](https://github.com/vishalmysore/layaAgent/blob/main/docs/article.md)의 한국어 요약이며, 한국어판에서 달라진 점을 덧붙입니다. 원본의 수치는 **영어 체크포인트 + 영어 과제**에서 나온 것이고, 한국어판의 수치는 아직 재지 못했습니다(아래 "측정 상태").

## 문제

요즘 에이전트는 단계마다 큰 생성 모델을 부릅니다. 도구를 고르고, 인자를 쓰고, 언제 멈출지 판단하는 일을 전부 LLM이 합니다. 느리고, 비싸고, 같은 입력에도 답이 흔들립니다.

layaAgent는 이 일을 칸네만식으로 나눕니다.

- **System 1 — Laya**: 타입화된 결정 인코더. 상황을 한 번 읽고, 정해진 선택지들의 확률을 돌려줍니다. 빠르고 결정적이며, 신뢰도를 숫자로 줍니다. **글을 쓰지 않습니다.**
- **System 2 — WebLLM**: 브라우저 탭 안에서 도는 작은 명령어 튜닝 LLM. 느리지만 추론하고 쓸 수 있습니다. System 1이 확신하지 못한 단계만 맡습니다.
- **사람**: System 2가 없거나(WebGPU 없음) 둘 다 확신하지 못하면 사용자가 고릅니다.

핵심 질문은 하나입니다. **에이전트의 일 중 얼마나 많은 부분이 생성 모델을 정말 필요로 하는가?** 답을 측정하려면 "System 1이 맡은 비중"과 "그 자동 단계의 오류율"을 **함께** 보고해야 합니다. 비중만 높이는 것은 임계값을 낮추면 되니까요.

## 한 단계의 흐름

```
목표 ─► 상태(목표·최근 4단계·마지막 관찰) ─► System 1: 다음 도구 선택, 목표 달성 여부, 위험 여부
     ─► 후보 추출기(모델 아님): 장소·사람·날짜·수량·산술·인용문
     ─► System 1: 슬롯마다 "이 중 어느 것인가" (후보 + NONE)
     ─► 게이트: AUTO면 그대로 실행 / HOLD면 System 2 또는 사람
     ─► 가드: 무언가를 바꾸는 도구는 항상 승인
     ─► 도구 ─► 관찰 ─► 다음 단계 (FINISH는 도구 결과로 답을 조립)
```

"Laya는 쓰지 않는다"가 설계의 중심 규칙입니다. 선택지는 도구 등록부·추출기·고정 목록이 만들고, Laya는 고르기만 합니다. 그래서 System 1은 감사 가능하고, 같은 입력에 같은 답을 냅니다. 인자는 **고르기로 하는 추출**입니다: Laya는 "일본"을 쓸 수 없지만, 관찰 결과에서 찾은 후보 중 "일본"을 고를 수는 있습니다. 맞는 값이 본문에 없으면 NONE을 골라야 하고, 그 단계는 System 2(유일하게 글을 쓸 수 있는 구성 요소)로 넘어갑니다.

## 게이트와 가드

- 게이트는 단계마다 하나를 정합니다: **AUTO**(System 1의 제안을 그대로 실행), **HOLD**(System 2가 결정, 없으면 사람).
- 보류 이유는 항상 화면에 보입니다: 행동 점수가 임계값보다 낮음, 어떤 인자의 점수가 낮음, 인자가 NONE, 직전과 같은 도구, 목표가 위험해 보이는데 읽기 전용 도구, 단계 예산 도달.
- **가드는 게이트와 별개**입니다. `note_save`, `note_delete`, `send_message`는 누가 골랐든 항상 확인을 요청합니다. 게이트는 "누가 결정할까"를, 가드는 "실행해도 되는가"를 다룹니다.
- 임계값은 슬라이더입니다. 움직이면 저장된 결정을 **모델 호출 없이** 다시 라우팅합니다. 무엇이 달라지는지 즉시 볼 수 있습니다.

## 영어 원본에서 측정된 것 (참고)

테스트 71과제·158단계, 노트북 Intel Iris Xe + WebGPU, System 2 = Qwen2.5-1.5B:

| 라우터 | 과제 성공 | System 2/사람 호출 |
|---|---|---|
| System 1 단독 (게이트 없음) | 32% | 0 |
| **Laya + 사람** (τ=0.65) | **94%** | 단계의 68%를 사람이 |
| Laya + System 2 (τ=0.65) | 21% | 158단계 중 107 |
| System 2 단독 | 10% | 158 |

τ=0.65에서 **Laya가 혼자 결정한 단계는 32%, 그중 90%가 맞았습니다.** 흥미로운 결과는 두 가지입니다. 첫째, 421M 인코더가 이 일(선택지 중 고르기)에서는 1.5B 생성 모델을 이깁니다. 둘째, 게이트는 정직합니다. 확신하지 못한 단계는 조용히 틀리는 대신 눈에 보이게 보류됩니다.

원본의 한계도 그대로 적혀 있습니다. 107개 합성 목표는 벤치마크가 아니라 연기 테스트이고, 지연 시간은 통합 GPU 하나에서 잰 값입니다. Laya는 한 도구로 끝나는 목표(날씨·계산·단위·날짜·기억)에 강하고, 상태를 이어가는 일(다단계 연결, 언제 끝낼지)에 약합니다.

## 한국어판에서 바뀐 것

1. **모델**: 영어 ModernBERT 421M 대신 다국어 mmBERT 322M 체크포인트(`convaiinnovations/laya-multilingual`). 특수 토큰을 하드코딩하지 않고 토크나이저에서 읽도록 고쳐, 같은 페이지가 두 계열 체크포인트를 모두 돌립니다.
2. **언어 정합**: 질문 지시문·선택지 라벨·도구 설명·게이트 이유·답변 템플릿을 모두 한국어로. 이전 Laya 한국어 작업에서 확인한 규칙 — **질문 언어와 선택지 라벨 언어가 같아야** 점수가 살아납니다.
3. **후보 추출**: compromise.js는 영어 전용이라, 한국어는 `web/ko.js`의 결정적 규칙으로 바꿨습니다. 조사 분리(은/는/이/가/을/를/의/에/에서/에게…), 고유명사 사전(지명·인물·기관 약 130개), 날짜(`2026년 3월 4일`, `3월 4일`), 기간(`3주 후`, `10일 전`), 수량(`5마일`, `20도`), 산술(`2,450의 18%`, `2의 10제곱`), 인용문(`…라고 기억해`, `…다고 전해`). 모델은 쓰지 않습니다.
4. **도구의 언어**: 한국어 위키백과, Wikidata 한국어 검색·라벨, Open-Meteo 한국어 지명(실패하면 사전의 영문 이름), 한국어 날짜·단위·숫자 형식, 한국어 관찰 문장.
5. **과제 세트**: 68개 한국어 목표, 147단계, 같은 11개 분류. 정답 인자가 후보 선택지에 실제로 나오는지 빌드 스크립트가 검사합니다(현재 실패 0건).

## 측정 상태

한국어판의 모델 수치는 **아직 없습니다**. 준비(모델 연결, 과제 세트, 추출기 검증)는 끝났지만, 이 기기의 도구 브라우저가 세션 도중 멈춰 브라우저 내 추론 녹음을 끝내지 못했습니다. Node에서 onnxruntime-web을 돌리는 우회로도 iSH의 WebAssembly가 `Illegal instruction`으로 죽어 실패했습니다.

그래서 이 저장소에는 한국어 성능 표가 없습니다. 대신 `eval.html`이 있습니다: 모델을 불러오고 "실행"을 누르면 테스트 45과제·147단계를 돌려 분담률·자동 단계 오류율·라우터별 성공률·System 1의 구성 요소별 정확도를 계산합니다. 숫자는 추측해서 적지 않습니다.
